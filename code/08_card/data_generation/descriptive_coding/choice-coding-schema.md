# Card declaration choice schema v1.1

Status: v1.1 preserves the v1 pilot schema and makes the audited display-level clarification below. This is a newly specified descriptive coding scheme, developed after the feasibility inspection in `PROPOSAL.md`; it is not preregistered. It describes final declared choices and does not reconstruct search chronology or recalculate independent model/null verdicts.

## Evidence and masking

Code the frozen public declaration and its hash-bound supplied context. Preserve exact source spans with JSON pointer or line coordinates, the unmodified source SHA-256, and a SHA-256 of every quoted span. A codebook can resolve an alias or status code, but cannot supply a probability assumption absent from the declaration. Code/report evidence may corroborate variables, filters and calculations only when available and source-bound; explicit commitment conflicts remain flagged rather than silently resolved.

During coding, conceal stratum, realized coefficients/p-values/counts, accepted match verdict, verdict rationale and post-reveal comparison. Retain numeric formula weights, status identifiers, null constants, and declared design thresholds. Masking is best effort: source prose can reveal features of an analysis. Record masking failures. Join the immutable reviewed verdict and stratum only after descriptive coding is locked.

Each displayed dimension has exactly one category per case. A case can have a clear outcome and an unclear sample; preserve the clear fields. `other` means explicit but outside the displayed bins, `unclear` means missing/ambiguous/conflicting evidence, and `mixed` means multiple selected alternatives without a uniquely designated commitment. These distinct detailed states share the displayed `other_unclear` residual. Do not call a missing declaration a negative choice or nonmatch. Terminal/classifiability disposition is a separate field controlled by the accepted source.

## Employment measure

Display codes: `nonmanager_fte`, `manager_inclusive_fte`, `employee_headcount`, `full_time_employees`, `other_unclear`.

- **Nonmanager FTE:** explicitly full-time employees plus one-half part-time employees, excluding managers. A defined alias is sufficient. Generic “FTE” without a definition is unclear. Other stated part-time weights belong to `other_unclear` with `base_measure=other_weighted_employment`.
- **Manager-inclusive FTE:** the preceding FTE definition plus an explicitly included manager count or explicit manager-inclusive definition. Record the manager weight; an unspecified manager weight remains unresolved at the formula level and is flagged even if manager inclusion is clear.
- **Employee headcount:** unweighted full-time plus part-time employee count, optionally plus managers. Record managers as included/excluded/unspecified separately; never infer exclusion from the word “employee.” Manager-inclusive headcount is not manager-inclusive FTE.
- **Full-time employees:** explicitly the full-time employee count alone, such as empft, with manager inclusion retained separately. This was added uniformly after the fixed pilot exposed a material distinction. Part-time only, hours, wage bill and unspecified “employment” go to the residual.
- **Other/unclear:** other explicit base measures, ambiguous definitions, incompatible outcome definitions, or multiple primary outcomes. Preserve a uniquely selected primary outcome even if the report also explores secondary outcomes. A declared vector/joint primary has `base_measure=mixed`.

Keep `outcome_formula_raw`, `base_measure`, `manager_inclusion`, `manager_weight`, `part_time_weight`, `transformation`, `scale`, and `contrast`. The displayed bin describes the employment base, so log FTE remains in its FTE bin with `transformation=log`; it does not imply the original outcome was selected. Full-time share, empft/(empft+emppt), is `base_measure=employment_share` in the residual and is not full-time count or headcount. Record `contrast` as change/post level/pre level/panel level/ratio/other/unclear. Preserve exact order and direction, such as post minus pre, plus logs versus log differences versus percentage changes. Winsorization, trimming, standardization and imputation must be recorded rather than treated as harmless aliases.

## Sample treatment

Display codes: `complete_case_no_status_filter`, `respondents_only`, `closure_recoding`, `other_unclear`.

Apply the stated eligibility operator, independent of realized sample counts. Equal observed samples do not make different declared rules identical. “Complete case” alone must be qualified by the declared outcome/regressors, baseline eligibility, status rule and missing-component treatment.

- **Complete cases; no status filter:** uses required observations for the selected analysis without conditioning on response/status labels. Ordinary exclusion of missing required outcome/covariate values qualifies. Record required waves and variables. “Balanced panel” alone is insufficient unless the relevant waves and missingness requirement are clear.
- **Respondents only:** explicitly restricts follow-up eligibility to the codebook-defined responding/open group, without including closed stores through zero recoding. Baseline complete-case eligibility is allowed and must be recorded. A further restriction such as a single chain, geographic subset, balanced subgroup or baseline-employment threshold moves the display to the residual.
- **Closure recoding:** explicitly admits a codebook-defined closed group, sets the relevant follow-up employment measure to zero, retains a defined baseline eligibility rule, and uses a stated eligible status set. Explicit all-status/no-extra-status-filter eligibility is a valid stated set when there is an explicit permanent-closure zero-recoding operator. Broader status filtering without closure recoding is residual. Observed recorded zeros alone are never a recoding operator. If the closure group, zero-recoding operation or eligibility is ambiguous, use the residual. Record whether follow-up raw counts for closures are required, not required, or ambiguous; all are closure-recoding variants, not proven identical eligibility. Explicitly incompatible status filters remain conflicting/unclear. Zero-filling missing employee components for respondents is not closure recoding.
- **Other/unclear:** mixed rules across groups/waves/outcomes, extra substantive sample filters, closure exclusion under otherwise broader status selection, imputation beyond closure recoding, unclear missingness/status rules, or several primary samples. An explicit mixed rule receives `sample_state=mixed`, not a silently selected “main” sample.

Retain `analysis_unit`, `baseline_eligibility`, `followup_status_eligibility`, `status_code_map`, `required_variables`, `missing_component_rule`, `closure_rule`, `closure_followup_requirement`, `other_filters`, `support_conditions`, `outcome_domain`, `failure_conditions`, `cross_wave_rule`, and `sample_state`. Keep exact Boolean eligibility statements where present. Distinguish a global estimability check (both states, at least two chains, identifiable terms; stop otherwise) from an actual row/subgroup filter. Requiring both states within chain is a support condition unless the declaration explicitly drops chains/rows. Positive denominators defining a share are intrinsic outcome-domain conditions, recorded separately without changing an otherwise clear respondent bin; a substantively chosen extra threshold/subgroup enters the residual. Required variables can include unmodeled measures (for example complete part-time counts with a full-time outcome); retain this difference without changing the basic status bin. Do not presume that a follow-up interview response implies nonmissing outcomes, or that closure status alone establishes a baseline observation. Weights belong in a separate detail field and are not a missingness rule.


## Specification display clarification (v1.1)

The third display column is **Specification**, grouping the declared regressor set and regression form. Its internal key remains `mean_model`. A population linear projection can therefore share a regressor/form bin with an explicitly stated linear conditional mean, without claiming that the two impose identical probability restrictions. All exact declarations and projection/conditional-mean distinctions remain in the evidence; the existing independent model/null verdict is untouched. Apply this clarification uniformly to the seven projection declarations identified by the full-cohort sweep. Six retain their prior displayed bin; one gains the explicitly declared baseline-headcount covariate. The original v1 conditional-mean-only wording below is superseded for the display by this specification-form interpretation. Other v1 rules and all case-level evidence remain applicable. No empirical result or match label is selected or revised through this change.

## Specification (legacy internal key: mean_model)

Display codes: `nj_additive_chain`, `nj_only`, `added_baseline_covariates`, `other_unclear`.

- **NJ + additive chain:** a declared linear change-score mean with intercept, NJ indicator and additive chain indicators only. Explicitly equivalent change notation qualifies; semantic equivalence must be documented. A label such as “DiD with chain controls” without the required formula/conditioning interpretation is insufficient. Use the actual conditional-mean declaration, rather than inferring it from OLS.
- **NJ only:** a declared linear change-score mean with intercept and NJ indicator only. An explicit contrast of two unrestricted state-specific mean changes with no other covariates also qualifies: the two group means are a direct saturated parameterization, not a new distribution assumption. Record this representation rather than invent an equation in quoted evidence.
- **Added baseline/covariates:** a declared linear comparative mean with additional baseline employment or other covariates beyond NJ and optional additive chain. It includes a clearly declared post-level ANCOVA with baseline outcome; retain that form in `time_form`. It does not absorb interactions or nonlinear models. Preserve exactly which controls and their functions were selected.
- **Other/unclear:** panel-level/time-interaction models without an explicitly established change-score representation, interactions that modify the NJ contrast, nonlinear mean/link, state-specific slopes, chain-by-state interactions, unspecified conditional-mean structure, conflicting declarations, or multiple primary models. A sole state-by-post term in a panel DiD is recorded as `time_form=panel_did` in the residual; do not mistake the word “interaction” alone for extra substantive treatment heterogeneity or claim automatic equivalence to an additive change model.

Keep `mean_formula_raw`, `time_form`, `link`, `intercept`, `treatment_term`, `additive_chain`, `extra_covariates`, `interactions`, `fixed_effects`, `weights`, `offsets`, and `mean_state`. `time_form` values include change_score, post_level_ancova, post_level, panel_did, panel_other, other, unclear. A generic regression formula documents a fitted calculation; it cannot manufacture a declared conditional-expectation restriction. Transformation of the outcome is retained under outcome, regardless of the displayed mean bin.

## Substantive restrictions and ancillary inference

Retain exact null, contrast parameter, sidedness, target population and analysis unit. Record explicit probability, distribution, variance and dependence restrictions with `role=substantive|ancillary_explicit|ambiguous`. Distinguish finite-population claims, iid assumptions, conditional means, constant-effect restrictions, independence, normality, homoskedasticity and identification assumptions when declared. A restriction is ancillary only if its stated role supports inference for an otherwise separately specified substantive model; uncertainty stays ambiguous. Never deduce any of these from a standard-error label or code.

Store HC0/HC1/HC2/HC3, clustering, t/normal reference, bootstrap, permutation/randomization, degrees of freedom, multiplicity and estimator separately under `inference`. An SE change alone cannot change a displayed substantive model category or the immutable reviewed endpoint. Preserve explicit statistical-model restrictions even when the inference procedure appears robust to them. This schema does not adjudicate match equivalence.

## Review and exact-signature reuse

An evidence signature is SHA-256 of a canonical JSON object containing the dimension name, complete relevant declaration spans, relevant alias/status-code context spans and source-role/conflict flags. Include all fields affecting that dimension: for sample, include outcome/covariate requirements; for mean, include the outcome contrast and full model context. Do not hash only extracted keywords or normalized formula fragments. Different whitespace/text can create additional signatures; this costs review time but avoids lossy merging. Evidence-source hashes and case IDs remain in the per-case record, outside the reusable semantic signature.

Every unique signature requires a semantic decision with evidence, reviewer and reason. Direct, unambiguous formula/eligibility phrases can be reviewed in compact field-level evidence tables; a fresh paragraph-by-paragraph model/null equivalence adjudication is unnecessary. Exact signature reuse is allowed only after the originating semantic decision is reviewed. A changed/null/mixed/conflicting/absent field is flagged; do not copy a decision from a superficially similar case. Case-level coherence review must catch conflicting dimensions, such as declared closure recoding combined with a filter that excludes every closure. Group signatures across dimensions only for efficient reading, never to waive this coherence check. Regex/parser candidates may prioritize review and emit flags; their outputs are not verified semantic codes. An audit sample complements the required evidence inspection and never certifies unreviewed lexical assignments.

Full-cohort agents should return one row per assigned case, a signature decision table, all flagged unique signatures and a case-level coherence result. No prevalence claims arise from the pilot. Report exact number of cases/unique signatures reviewed when complete; do not describe a lexical pass as semantic review.

## Pilot design

Take 48 unique IDs with the smallest bytewise SHA-256 digest of UTF-8 `card-trace-schema-pilot-v1` + NUL + case ID across all 3,000 source IDs; ties sort by case ID. Selection uses no strata, numeric results, verdicts, content or source order. Freeze the ID/hash manifest before reading pilot packets. Unavailable/masked-away declarations stay in the pilot and cannot be replaced by more informative cases. This is a schema stress test, not an estimate of category shares. The numerical/stratum/redaction handling and actual pilot manifest are recorded separately.

After pilot inspection, freeze uniform rules and the pilot evidence ledger; document changes before full-cohort coding. If the full pass reveals an unhandled distinction, version the schema and apply the revision uniformly to all affected signatures/cases, preserving earlier decisions. Keep published denominator/disposition and accepted verdict reconciliation separate from descriptive taxonomy.
